# TASKS

*Three natures, not two, not one.*

---

## The three natures

| Nature | Emoji | Description | End |
|--------|-------|-------------|-----|
| **One-off** | 📌 | Single action, window of relevance | When it's done |
| **Rhythm** | 📊 🧹 🔧 🤝 | Discipline — regularity is the goal | Never |
| **Worksite** | 🏗️ | A single commitment with sub-tasks — the goal is to finish | When it's complete |

## Rhythm categories

Rhythms are not a homogeneous block. What they maintain determines what their disruption signals:

| Emoji | Category | What it maintains | What disruption signals |
|-------|----------|------------------|------------------------|
| 📊 | Tracking | Indicators, metrics | Reality is masked |
| 🧹 | Hygiene | What degrades without attention | Degradation takes hold |
| 🔧 | Maintenance | Tools and infrastructure | Means become fragile |
| 🤝 | Attention | Relationships, bonds | Bonds erode |

These categories are not prescribed — they emerge from instantiation.

## Naming

Each task is a `.md` file. The name follows the format: `[partition] [nature] Description.md` or, when the task belongs to a project, `[partition] [nature] PROJECT — Description.md`.

Three or four segments: *where* · *what* · (*project*) · *name*.

Examples:
- `💰 📌 File taxes.md`
- `💪 📊 Weekly weigh-in.md`
- `🏡 🏗️ Renovate bathroom.md`
- `🧠 🏗️ HELIOS — Validate dataset.md`

The name is self-contained — readable in its partition folder as well as in cross-cutting views (allocation, journal, weekly review). The project prefix makes every task identifiable without folder context. Simple tasks that don't belong to a project skip the prefix. An optional `Project:` field in the frontmatter mirrors this for programmatic use.

## Mutations

Tasks change nature — and the change carries more information than the task itself.

- A one-off that lingers → perhaps a disguised worksite
- A broken rhythm → signal differs by category
- A stalled worksite → perhaps needs re-scoping or letting go

The guardian spots mutations during grooming.

## The worksite as a single document

A worksite is a single commitment — not a series of separate tasks. It exists as a single file that can contain sub-tasks (a graph of what remains to be done). The guardian presents relevant sub-tasks in the allocation.

A worksite can be linear (a queue of similar elements) or non-linear (different steps toward a result). Linear ones are counted, non-linear ones are milestoned.
