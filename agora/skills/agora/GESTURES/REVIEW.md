# REVIEW

Pass the instance in review with the user, and leave the trace that lets anything leave.

## Intention

The written state of the whole is not the true state. Before anything leaves, present what the instance holds, look for what has changed, and have the user confirm or correct — systematically, even when nothing seems to have moved. A declaration that is stale presents itself as current; this gesture is what keeps that from reaching a consumer.

## When

- **Before every exit.** PACKAGE refuses without a review of the current revision
- A piece has appeared, been delivered, split, merged, or been retired
- On request — the user wants to know what the whole currently holds

## Input

- The instance (`MANIFEST.md`, at the head of the corpus's place)
- The corpus as it stands: its places and the criterion each declares; every piece's README (nature, source method, conditions) and deliverable
- The trace of what was done for each piece: its deliverable accepted or not (version control — the deliverable on the main line, the tag set at its delivery), and the version each channel serves (the destination, read as the system file says)
- The revision identifier of the corpus
- What the deliverables say of their neighbours — a section of dependencies, a relation to another piece, a citation — and the corpus's topology where it keeps one
- For each unit, the system file it targets (limits that composition must respect)

## Output

- The instance confirmed or corrected, with **Last review** set to the current revision — **Reading order** included
- The user has seen every difference between what was written and what is there, and has decided each one
- For each version that would leave, the channel it goes to — proposed here, confirmed by the user, written nowhere: the transport that follows is its trace

## Sequence

1. **Derive the candidates.** For each unit, apply its composition rule to the corpus *as it stands* — no list consulted. Add what the unit adds in its own right. Silence counts as candidacy: a piece the rule designates comes up whether or not it declares anything.
2. **Read each candidate at home, and in its trace.** Its README: nature, source method, conditions of application. Its deliverable: present, with its presentation. Its trace: accepted or not, which version each channel serves. Note what is undeclared — do not infer it.
3. **Detect what moved** since the last review. A piece that exists and the instance does not know. A deliverable that changed. A piece that declares a different nature. A version delivered and served nowhere yet. A folder that split or disappeared. A place without its criterion, a piece in two places, a piece in none. Detection assists; it does not conclude — the criteria themselves are the corpus's, not this gesture's to judge.
4. **Show, then ask.** Present the instance as it reads, then each difference, one at a time: *this piece is now designated by the rule and has an accepted deliverable — does it go out? This one is designated and has none yet — still being designed, confirm? This one is paused — does the reason still hold? This one has no declaration — ask its author, or decide anyway?* The user answers; this gesture writes.
5. **Propose how far each version goes.** For every version that would leave, say what the trace reads and where you would send it: a new version, to a few first; a version already served to a few and unchanged since, ask whether it goes to all. The user follows or corrects — a minimal change may go straight to all, a simple-looking one may stay on trial. The answer holds for this version; it is a proposal with a reasonable default, not a rule.
6. **Analyse how the pieces combine, and give the opinion.** For every piece some unit reads together with others, read what its deliverable says of its neighbours and tell two relations apart: what it **presupposes** — it cannot be understood without the other — and what it **frames** — it serves the other as a lens without presupposing it. Propose **Reading order**: the pieces that frame first, then each after what it presupposes. Flag every unit whose selection takes a piece without what that piece presupposes. Say an inference as an inference — where a deliverable says nothing, the relation is read in what it does, not declared. The user confirms or corrects; then write the list. A piece selected and not placed would stop PACKAGE.
7. **Check who holds the main thread.** At most one unit per destination adds a persona that is the session's agent; the others are dispatched beside it. Two claims are shown and decided here — the system would keep one in silence.
8. **Record movements.** Where the user confirms that something moved between pieces — a section that left one grammar for another, a method retired — write it under **Movements**: what, from, to, retired. Erase entries whose delivery a previous review already followed.
9. **Check the limits.** With the composition confirmed, does any unit exceed a limit its system file states — a payload ceiling, a count? Show it; the answer is a composition decision, not a packaging trick.
10. **Set the trace.** Write the current revision under **Last review**. From here until the corpus moves again, PACKAGE may run.

## Guardrails

- **Systematic, even without a clue.** The review is not triggered by detection; detection serves the review. A review skipped because "nothing changed" is exactly the one that would have caught the change nobody noticed.
- **Show the state, not a summary of it.** The user confirms what they see. A review that says "all fine" has confirmed nothing.
- **Maturity is read in the trace, never written.** Not in the instance, not in the README: what an act already says, a second text would only contradict one day. Only the pause is written, with its reason — no act carries it.
- **Neither refuse by default nor let through in silence.** A designated piece with no accepted deliverable, a delivered piece that is paused: in both cases the gesture shows the gap and asks. It never resolves it alone.
- **The question is automated, not the answer.** A piece delivered since the last review does not enter a unit by itself; the review shows it and the user decides. Push is conscious.
- **The order is the corpus's, the selection the unit's.** Write the order once, in **Reading order**; never in a composition, never copied from a persona. A persona declares what it mobilises, not in what order.
- **The trace is a revision, not a date.** Anything that moves the corpus invalidates it. That is the point: no stamp to nod at.
