# ABSTRACT

Extract orthogonal dimensions from the Sketch.

**When:** The Sketch reveals that the domain has hidden dimensions worth exploring — spectrums, trade-offs, tensions that a direct consolidation would miss.

**Input:** Sketch in `1a. Sketch/`.

**Output:** Angles in `1b. Angles/`.

**Sequence:**
1. Reread the Sketch — what patterns does it show?
2. What dimensions underlie these patterns? What are the spectrums?
3. For each candidate dimension: is it orthogonal to the others? Two angles that say the same thing in different words are one angle.
4. For each angle: name the two poles. List the salient characteristics of each pole.
5. Write each angle using the template below.
6. Check: is the set minimal? Does it cover the space of meaningful choices?

**Guardrails:** Angles describe — they do not choose. Each angle is a spectrum, not a recommendation. If you find yourself favoring a pole, you have left Angles territory and entered Position.

The goal is a minimal set of independent dimensions. More angles is not better — fewer, orthogonal angles map the space more clearly.

**Angle template:**

```
# [Name]

## Dimension

[pole A] ↔ [pole B]

## Characteristics

**[Pole A]**
- [salient characteristic]
- ...

**[Pole B]**
- [salient characteristic]
- ...
```

Each pole lists what makes it distinct. A characteristic appears where it is salient.

**Source method:** Kyklos (knowledge refinement module — Organon only).
